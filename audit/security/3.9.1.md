# Security review - BuddyPress Group Reviews 3.9.1

Diff reviewed: `v3.9.0..3.9.1`. Environment: wbcom-free.local, WordPress 7.1, BuddyPress 14.x, PHP 8.2.

## Findings fixed in this release

| Severity | Where | Attacker story | Fix |
|---|---|---|---|
| HIGH | `includes/bgr-bp-rest-integration.php` - GET `/buddypress/v1/groups/{id}/reviews`, `/reviews/{id}` (`permission_callback => __return_true`) | A logged-out visitor walks group IDs and reads every review (text, reviewer, ratings) of private and hidden groups; the single route also served pending (unmoderated) reviews on any group. | `read_reviews_permissions_check()` via `bgr_can_view_group_reviews()`; pending reviews need `edit_review`. |
| HIGH | `add_review_data_to_response()` on BuddyPress `GET /groups/{id}` | BuddyPress returns private groups to outsiders; our filter embedded their average and per-criterion ratings. (QA bounce.) | Embed skipped unless `bgr_can_view_group_reviews()`. |
| HIGH | `bp_group_review_filter_ratings` (`wp_ajax_nopriv_`) | The logged-out nonce printed on any public page let anyone POST a private/hidden `group_id` and receive its reviewers and ratings. Found by the G1 sweep after the REST fix. | Returns 403 unless `bgr_can_view_group_reviews()`. |
| MEDIUM | Group header rating, JSON-LD `AggregateRating`, group rating widget, top rated widget | Private group page is served to outsiders by BuddyPress and showed the aggregate rating; the widget listed hidden groups (name, avatar, link, rating) to everyone. | All gated by `bgr_can_view_group_reviews()`. |
| MEDIUM | `uninstall.php` | Not an attack - data loss: uninstall deleted every `review` post, including BuddyPress Member Reviews (shared CPT), and ran an unescaped `LIKE '%bgr_%'` delete on usermeta. | Deletes only reviews with `linked_group`; usermeta delete removed. |
| LOW | `bgr_handle_review_submitted()` / `bgr_handle_review_decision()` emails | A member names a group with HTML; the markup lands live in the HTML email sent to the group admin / reviewer. Carried over from the old inline handlers. | Values escaped before substitution. |

Rule now used everywhere a group's reviews or ratings are shown: public group -> everyone; private or hidden group -> members and `bp_moderate`. This matches BuddyPress, which also hides a private group's member list and member count from outsiders.

## Scanner-visible but safe

- `includes/bgr-shortcodes.php:348,384` - `[bgr_display_top_groups]` queries interpolate only a hard-coded `ORDER BY` clause and `$wpdb` table names; values go through `prepare()`; restricted to `g.status = 'public'`.
- `includes/widgets/bgr-review.php` group-ID `DISTINCT` query - no request data; result cached in `bgr_widget_group_ranking`.
- `uninstall.php` transient `LIKE` uses `$wpdb->esc_like()` + `prepare()`.

## Open, not blocking (pre-existing)

- CSV export writes review text as-is; a review starting with `=`, `+`, `-` or `@` is treated as a formula when an admin opens the file in a spreadsheet (CSV injection). Admin-only download. Card to be filed.
- Contract audit warnings: `bgr_delete_custom_criteria` and `bgr_toggle_global_criteria` AJAX handlers have no in-plugin caller (unchanged since 3.9.0).
