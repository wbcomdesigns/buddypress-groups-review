# BuddyPress Group Reviews 3.9.1 - QA handoff

**Branch:** `3.9.1` (from `master`; https://github.com/wbcomdesigns/buddypress-groups-review/tree/3.9.1)
**Basecamp:** BuddyPress Group Reviews board - every card below is in **Ready for Testing** with a verdict comment that has the full detail.
**Goal:** QA confirms every fix on this branch. Release (version bump, changelog, POT, manifest, zip) starts only after all cards pass.

Plugin direction: stabilize then freeze. These are fixes only - no new features. Three requests were declined by the owner and are in **Not now** (see "Not in this release").

---

## 1. Setup

1. Check out branch `3.9.1` and run `npx grunt cssmin uglify rtlcss` (or use the committed `min/` files - they are already rebuilt on the branch).
2. Test on **Reign**, **BuddyX**, **BuddyX Pro**, and one default theme (**Twenty Twenty-Five**). Check light **and** dark mode on Reign/BuddyX (use the theme's own dark-mode toggle in the header).
3. Viewports: **1440**, **1024**, **390** for every front-end screen.
4. Emails: read them in the site's Mailpit (Local → site → Mailpit). Do not trust "sent" logs - open the actual email.
5. BuddyPress Groups, Activity and Notifications components must be active.

### Roles you need (create if missing)

| Role | Used for |
|---|---|
| Site admin | wp-admin settings, wp-admin approve/deny, bulk actions, CSV export |
| Group admin (of a private group) | Manage tab accept/deny, receives "new review" email + notification - **make sure this user has an email address** |
| Group member (not admin) | submits reviews |
| Logged-in non-member | must NOT see private/hidden content |
| Logged out visitor | REST and widget privacy checks |

### Data you need

- A **public**, a **private** and a **hidden** group, each with at least one published review.
- One public group with **more than 10** published reviews (pagination).
- 3 active review criteria (e.g. Quality, Relevance, Engagement).
- Settings → General: **Auto approve OFF** (so reviews go to pending) unless a step says otherwise.
- If BuddyPress **Member Reviews** is installed, keep a few member reviews on the site - several fixes must leave them untouched.

## 2. Cards to verify

Each section: what was wrong, what to do, what you should see. Commit IDs are for developers.

### A. Data integrity and privacy (test these first)

#### A1. Star ratings - crash or ratings saved against the wrong criteria (`6261d85`)
- **Was:** submitting with a different number of stars than active criteria gave a 500 error and lost the review; a form opened before an admin changed the criteria could save stars on the wrong criterion.
- **Steps (member):**
  1. Submit a review normally. Open it in wp-admin → each criterion shows the star you picked.
  2. Open the Add Review form in a tab. In wp-admin, add or remove a criterion and save. Back in the old tab, submit.
  3. Remove all criteria in wp-admin, open the form again (single "Your Rating"), submit.
- **Expect:** (1) correct per-criterion values. (2) message "The rating criteria have changed. Please reload the page and submit your review again." - no 500, no review created. (3) review saved with one overall rating (**not yet verified in dev - please confirm**).

#### A2. REST shows private/hidden group reviews to anyone (`6261d85`)
- **Steps:** with no login (incognito or curl), request `GET /wp-json/buddypress/v1/groups/{private_id}/reviews` and `/reviews/{review_id}`. Repeat for a hidden group, as a logged-in non-member, as a member, and as site admin. Also request a **pending** review by ID on a **public** group as logged out / non-author.
- **Expect:**

| | Logged out | Non-member | Member | Site admin |
|---|---|---|---|---|
| Private group list / single | 401 | 403 | 200 | 200 |
| Hidden group list | 401 | 403 | 200 (if member) | 200 |
| Public group list | 200 | 200 | 200 | 200 |
| Pending review on a public group | 404 | 404 | 200 for its author only | 200 |
| `GET /groups/{private_id}` - `reviews` key in the group object | absent | absent | present | present |

- Also check the **private group's page** as logged out / non-member: no rating in the group header and no `AggregateRating` in the page source. As a member: both present. Public groups: present for everyone. (Bounce fix `610640b`.)

#### A3. Uninstall deletes Member Reviews data / leaves Group Reviews data (`cc70806`)
- **Risk:** destructive - use a throwaway site.
- **Steps:** with Member Reviews installed and some member reviews present, add `define( 'BGR_REMOVE_DATA_ON_UNINSTALL', true );` to wp-config.php, then Plugins → deactivate → Delete Group Reviews.
- **Expect:** all group reviews, Group Reviews settings, per-group criteria and review caches are gone; **every Member Review is still there**; Member Reviews admin still works. Re-install Group Reviews → settings page opens normally.

#### A4. Top rated groups widget lists hidden groups + loads every review (`c9414d3`)
- **Steps:** Appearance → Widgets → add "BP Group Review Widget" (Top Rated, thumbnails Show) to a sidebar that shows on /groups/. Give a hidden group a 5-star review.
- **Expect:** logged out and logged-in non-member: hidden **and private** groups NOT listed. Site admin and members of those groups: listed. Publishing a new review changes the widget order on the next page load. The widget's rating for a group equals the "Rating: x/5" shown in that group's header.

### B. Emails, notifications, activity

#### B1. No email when a review is approved/denied from wp-admin (`0410a01`)
- **Steps (Emails tab: Review Acceptance + Review Denial ON):** approve and deny a pending review from **each** path: wp-admin row link, wp-admin **bulk** Approve/Deny, the group's Manage tab (as group admin), and the post editor (Publish).
- **Expect:** every approve sends "approved" to the reviewer; every deny sends "not approved". The approval email's link opens the **group's Reviews tab** (not wp-admin). Trashing an already **published** review sends nothing.

#### B2. Notifications toggle OFF still notifies (`6261d85`, `0410a01`)
- **Steps:** General → BuddyPress Notifications OFF, Review Activity ON. Submit a review as member; approve/deny reviews from wp-admin, bulk and Manage tab.
- **Expect:** no new review / approve / deny notifications for anyone. Turn it back ON → notifications appear again.

#### B3. Review activity type missing from the activity filter (`8128836`)
- **Steps:** approve a review on a public group (activity ON). Go to /activity/ → Show: dropdown. Also check the group's Activity tab filter and a member's profile Activity filter.
- **Expect:** "Group Reviews" option is present; selecting it lists only group-review activity.

#### B4. Hook / REST-created reviews skip side effects (`a049d1f`)
- **Steps (developer-assisted):** create a review via `POST /wp-json/buddypress/v1/groups/{id}/reviews` as a member, and one via the form.
- **Expect:** both get the review category "Group", notify and email the group admin, and (with auto-approve ON) create activity. `bgr_group_review_after_review_insert` receives (review ID, group ID, reviewer ID) on both paths - see `docs/DEVELOPER-GUIDE.md`.

### C. Admin screens

#### C1. Criteria Remove/Add buttons (`f1c0a56`)
- **Steps:** Settings → Criteria. Tab through the rows with the keyboard. Add a criterion, type a name, remove another, Save, reload. Check at 390px.
- **Expect:** Remove is a red text link (WordPress style), Add is a normal WordPress button; visible focus ring on both; screen reader reads "Remove Quality" etc. (new rows too, after typing). Saved list matches what you left. No horizontal scroll at 390px; Remove is easy to tap.

#### C2. CSV export memory (`eeac6cf`)
- **Steps:** Reviews → Export with 2,000+ reviews (developer can seed with WP-CLI).
- **Expect:** download completes; one row per **group** review (Member Reviews rows are no longer included); columns and values unchanged otherwise.

#### C3. Documentation link 404 (`6c811af`)
- **Steps:** click "Read Documentation" on the Welcome tab and the Documentation link in the settings sidebar.
- **Expect:** both open https://docs.wbcomdesigns.com/bp-family/buddypress-group-reviews/ directly.

### D. Front end - theme fit

#### D1. Pagination does not follow the theme colour (`158bec1`)
- **Steps:** open the Reviews tab of the group with 10+ reviews on each theme, light and dark.
- **Expect:** the current page button uses the theme's own button colour and text colour (compare with the theme's "Join Group" button). Reference values seen in dev: BuddyX/BuddyX Pro `#c92a2b` (dark `#ff6b6b` on `#0a0a0a`), Reign `#1d76da` (dark `#97c0ee` on `#15181f`), Twenty Twenty-Five `#111` on white. Changing the theme's button colour in the Customizer should change pagination too (**not yet verified in dev - please confirm**).
- **Open question on the card:** "group avatars in the sidebar" on BuddyX Pro was not reproduced - reporter to describe what is wrong.

#### D2. "Submit Feedback" button wraps to two lines (`158bec1`)
- **Steps:** Group Reviews → **Display** → rename the review label to "Feedback". Open a group's Add Feedback page on each theme, 1440 and 390.
- **Expect:** "Submit Feedback" on one line, theme button colours, no overflow.

## 3. Regression sweep (whole plugin, once)

Walk this once on Reign after the cards pass:

- Every settings tab loads and saves: Welcome, General, Criteria, Display, Emails, Discover.
- Member journey: join group → Add Review → see it pending → group admin approves on Manage tab → review shows on Reviews tab with stars → appears in activity → reviewer gets email + notification.
- Multiple reviews OFF: second review by the same member is blocked with "You have already submitted…".
- Group admin cannot review their own group; non-member cannot see the Add Review tab.
- Per-group criteria (group Manage → criteria): add, archive, save still works.
- Sort dropdown on the Reviews tab and pagination links work together.
- Member Reviews (if installed) still works end to end - shared post type.
