# Audit Verdict: buddypress-groups-review

**Branch:** 3.9.0 · **Audited:** 2026-07-03 · **Method:** STATIC ONLY (no browser, no code changes, no commits) · **Auditor:** AutoVAP product-readiness auditor

Scope: contract audit (meta/option keys, hooks, JS↔PHP AJAX wiring, CSS orphan rules), security (caps/nonces/escaping/ownership), performance (big-site checklist on every list/query), UX-token drift, three-entry-points, i18n.

---

## Shippable? WITH FIXES

Core moderation flow (submit → accept/deny/remove), settings persistence, and the wrapper migration are solid — nonces + caps are checked correctly everywhere, no SQL injection surface (no raw `$wpdb`), no unescaped output, no IDOR on the AJAX moderation endpoints. **But two customer-facing unbounded queries must be fixed before this ships to any site with a non-trivial group/review count**: one fires on the BuddyPress **groups directory** (the highest-traffic page on any BP site) once per group card rendered, the other on the group Reviews tab's default "Highest/Lowest Rated" sort option. Both defeat the plugin's own pagination and will degrade or time out pages at scale — exactly the class of bug the portfolio's big-site checklist exists to catch pre-release, not post-incident.

## Sellable? WITH POLISH

Security posture is genuinely good and the 3.9.0 wrapper migration (per `WRAPPER-AUDIT.md`/`BUILD-LOG.md`) closed real gaps (alert/confirm removal, tap targets, dark mode). What holds it back from "premium quality": two dead-UI AJAX endpoints (delete/toggle criteria buttons that don't exist), zero i18n coverage on all new JS-driven UI text despite the plugin actively shipping translations, and 19 keyboard-focus-indicator regressions across the CSS. None of these are exotic — they're the kind of thing a demanding customer or a translator will hit in week one.
